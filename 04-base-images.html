Cheat sheet · 04

The two Instruqt-provided container images and the custom-image option for VMs. Choose by what your assignments need to run.

gcr.io/instruqt/shell

Lightweight

Boot time
< 30 seconds
Footprint
Small

Includes

  • bash, common shell tools
  • curl, wget, jq
  • git, vim, nano
  • Instruqt agent helpers (fail-message, set-status, agent variable)

Does not include

  • Cloud CLIs (aws, az, gcloud)
  • Heavy language runtimes
  • Database clients
Use for: tracks that only need a Linux shell. Container-only labs, terminal-focused tutorials, anything where the lightest possible boot is worth more than tooling completeness.

gcr.io/instruqt/cloud-client

Full toolkit

Boot time
~ 45 seconds
Footprint
Heavy

Includes

  • All of shell contents
  • aws CLI v2
  • az CLI
  • gcloud SDK
  • kubectl, helm
  • terraform, jq, yq

Does not include

  • Vendor-specific tools (install in setup)
Use for: any track with an aws_accounts, azure_subscriptions, or gcp_projects block. The boot tax pays for itself the moment a learner types aws s3 ls.
Trap: reaching for shell with a cloud account block produces "command not found" errors during the demo. Either switch image or install the CLI in setup.

Custom GCP images for VMs

For VM-based tracks needing heavy preinstalled dependencies — vendor product builds, seeded databases, multi-gigabyte ML models — bake them into a custom GCP image and reference it as <project-id>/<image-name> in the image: field of a virtualmachines block.

Trade-off: faster lab boot (no install at runtime) versus ongoing image maintenance (rebuilds when the vendor product or base OS updates). Worth it when install-at-setup-time would exceed several minutes; not worth it for tools that install in seconds.
