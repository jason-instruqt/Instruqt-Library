agent variable + Instruqt-Var

Cheat sheet · 10

The platform's mechanism for moving values between hosts, between challenges, and into the assignment body.

Cross-host hand-off

1. Set on host A

# in setup-host-a
DB_ENDPOINT=$(aws rds describe-db-instances \
  --query '...' --output text)

agent variable set DB_ENDPOINT "$DB_ENDPOINT"

Where: any lifecycle script. Value is now scoped to the lab session and visible from any host in the track.

2. Read on host B

# in check-host-b
DB_ENDPOINT=$(agent variable get DB_ENDPOINT)

psql "host=$DB_ENDPOINT ..."

Where: any lifecycle script on any host. The value persists across challenges within the same lab session.

Interpolation in assignment.md

The database is reachable at:

[[ Instruqt-Var key="DB_ENDPOINT" hostname="workstation" ]]

Resolved at render time, substituting the value the script set. hostname must match the host where agent variable set ran.

What goes where

Mechanism Use for Visible to learner?
Auto-injected env var Platform-provided values: cloud creds, participant ID. Set automatically. Yes — visible in shell environment.
Secret (in config.yml) Sensitive values not in version control. Configured in platform UI. Visible if the learner inspects env, but not advertised.
agent variable Cross-host, cross-challenge state generated at runtime. Yes — readable by any process on any host.
Bash variable Ephemeral, single-script values. Process-local; gone when the script exits.

Patterns and gotchas

  • Provisioning hand-off: setup script writes a generated ID, check/cleanup scripts read it. Cleanest way to coordinate state across the lab.
  • Dynamic credentials: setup generates a password, stores via agent variable set, configures services to use it, surfaces it in the assignment via Instruqt-Var.
  • Multi-challenge state: a value produced in challenge 1 is read in challenge 3 via agent variable get. Combine with defensive challenge-level setup to survive learners who skip earlier challenges.
  • Not a secret store: agent variable values are visible to any process on any host the learner can access. If a value must be hidden from the learner, it does not belong here.
  • Set before read: a check or assignment that reads a variable before any setup script has set it gets an empty string. Set values in track-level setup or earliest challenge setup.
