Lifecycle scripts

Cheat sheet · 08

Bash scripts that run at specific points in a track's life. Filename suffix is always the host name (e.g. setup-workstation).

The four script types

setup-{host}

Runs: before the scope becomes active. Track-level: once, before challenge 1. Challenge-level: before that challenge.

Job: provision tools, seed data, write configs, start services, pre-pull images.

Exit: 0 success, anything else aborts the lab.

check-{host}

Runs: when the learner clicks Check.

Job: validate the learner's work AND teach when validation fails.

Exit: 0 = pass, 1 = fail. stderr/stdout surface in lab UI on fail.

solve-{host}

Runs: when the learner clicks Solve, or during testing.

Job: produce the exact state the matching check accepts as a pass. Must be idempotent and complete.

Exit: 0 success.

cleanup-{host}

Runs: at end of scope. Most tracks need none — the platform tears down resources automatically.

Job: undo external state (SaaS resources, remote APIs) the platform cannot clean up.

Exit: non-fatal. Use set -uo pipefail (no -e) so individual failures don't bail.

Script preamble patterns

Setup script header #!/bin/bash set -euxo pipefail until [ -f /opt/instruqt/bootstrap/host-bootstrap-completed ]; do sleep 1 done
Check script wrapper for subprocesses RESULT=$(curl -fsS "$API/healthz") || { fail-message "API health check failed." exit 1 }

Conventions and gotchas

  • Track-level scripts live in track_scripts/. Challenge-level scripts live inside the numbered challenge directory.
  • Filename suffix matches the resource name in config.yml. Misnaming silently disables the script.
  • set -euo pipefail is good defense — but unguarded subprocess failures cause silent bash exit and a generic "Something went wrong" modal. Wrap subprocess calls explicitly.
  • fail-message and set-status are container-only. On a VM they exit with status 127. Use plain echo + exit 1 on VMs.
  • agent variable set KEY VALUE on host A; agent variable get KEY on host B. Cross-host state across challenges.
  • set-workdir /workspace in setup makes terminal tabs open in that directory rather than /root.
