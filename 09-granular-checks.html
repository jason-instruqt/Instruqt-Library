Granular check pattern

Cheat sheet · 09

A check script's job is not to determine pass or fail. Its job is to teach the learner what they got wrong and how to fix it.

Principle: run each assertion independently. On failure, name the specific problem AND the exact remediation command. Each Check button click becomes a punch list, not a verdict.

Lazy vs. granular

✗ Lazy: chained assertions

psql -tAc "SELECT 1 FROM pg_roles
  WHERE rolname='analyst'" | grep -q 1 \
&& psql -tAc "SELECT has_table_privilege(
  'analyst','orders','SELECT')" | grep -q t \
&& psql -tAc "SELECT has_table_privilege(
  'analyst','orders','DELETE')" | grep -q f

if [ $? -ne 0 ]; then
  echo "User is not configured correctly"
  exit 1
fi

Learner sees: "User is not configured correctly." They re-read the assignment, run the same SQL, possibly start over. This is where learners abandon.

✓ Granular: one assertion at a time

if ! psql -tAc "SELECT 1 FROM pg_roles
   WHERE rolname='analyst'" | grep -q 1; then
  fail-message "User 'analyst' does not exist.
Run: CREATE USER analyst
     WITH PASSWORD 'changeme';"
  exit 1
fi

if ! psql -tAc "SELECT has_table_privilege(
   'analyst','orders','SELECT')" | grep -q t; then
  fail-message "User 'analyst' lacks SELECT
on orders.
Run: GRANT SELECT ON orders TO analyst;"
  exit 1
fi

Learner sees: a specific problem with the exact command to fix it. The Check button becomes a teaching tool.

What a great check script does

  • One assertion per block. Each if tests exactly one property; failure messages are specific.
  • Specific remediation. Failure messages name the exact command to run, not "review the assignment."
  • Wraps subprocess calls. RESULT=$(...) || { fail-message "..."; exit 1; } avoids the silent set -euo pipefail trap.
  • Validates intent, not state. Accept all valid terminal states (e.g. both enriched and governed) — don't insist on an intermediate label that may have been overwritten.
  • Container vs. VM aware. fail-message and set-status exist only on containers — fall back to echo + exit 1 on VMs.
  • Mirrors the solve. Every property the check tests, the solve script must establish. Test the pair end to end.
  • For certifications, score don't gate. Tally points across criteria, surface a color-coded scorecard, exit 0 / 1 by threshold.
