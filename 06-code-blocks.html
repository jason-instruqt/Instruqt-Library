Code block modifiers

Cheat sheet · 06

Modifiers placed after the opening fence and language identifier turn static code blocks into interactive UI in assignment.md bodies.

Modifiers

```bash,run Click-to-run in the active terminal. Most common form.
```run Click-to-run, no syntax highlighting.
```copy Adds a copy-to-clipboard button.
```nocopy Disables the default copy button.
```bash,wrap Wraps long lines instead of horizontal scroll.
```bash,wrap,copy Wrap plus copy. Useful for long one-liners.
```bash,nocopy,run Run-only, no copy button. For commands the learner shouldn't grab.
```bash Plain bash block. No run button. Use for snippets with placeholders.
Trap: ```bash {"run": "execute"} looks like it should work but is not valid Instruqt syntax. The block renders, but no run button appears. Always use comma-separated modifiers: ```bash,run.

Common combinations

Click-to-run command ```bash,run
aws s3 ls
```
Copyable long command ```bash,wrap,copy
curl -X POST ...
```
Snippet with placeholder ```bash
grant select on table
<TABLE_NAME> to analyst;
```
Plain reference output ```nocopy
Process completed.
```

Supported language identifiers

bash · python · javascript · js · typescript · ts · yaml · yml · json · dockerfile · hcl · aql · graphql · markdown · ruby · go · rust

Choosing the right modifier

  • Use bash,run for any command the learner should execute as-is.
  • Use plain bash (no modifiers) for snippets containing placeholders the learner must edit before running — this prevents the run button from appearing on broken commands.
  • Use nocopy on output blocks the learner shouldn't paste back into the terminal.
  • Modifiers can stack freely; order does not matter (bash,wrap,copy equals bash,copy,wrap).
