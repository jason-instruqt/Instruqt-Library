Instruqt environment variables

Cheat sheet · 03

Auto-injected into every lifecycle script. {NAME} matches the resource name in config.yml, uppercased with hyphens replaced by underscores.

General

INSTRUQT_PARTICIPANT_ID Unique ID for this lab session.

AWS account

INSTRUQT_AWS_ACCOUNT_{NAME}_*
ACCOUNT_ID12-digit AWS account ID.
USERNAMEIAM console login username.
PASSWORDIAM console login password.
AWS_ACCESS_KEY_IDProgrammatic access key.
AWS_SECRET_ACCESS_KEYProgrammatic secret.

Azure subscription

INSTRUQT_AZURE_SUBSCRIPTION_{NAME}_*
ADMIN_SPN_IDService principal client ID.
ADMIN_SPN_PASSWORDService principal secret.
TENANT_IDAzure AD tenant ID.
SUBSCRIPTION_IDAzure subscription ID.

GCP project

INSTRUQT_GCP_PROJECT_{NAME}_*
PROJECT_IDGCP project ID.
USER_EMAILProvisioned user email.
USER_PASSWORDProvisioned user password.
SERVICE_ACCOUNT_KEYUser-scoped service account JSON.
ADMIN_SERVICE_ACCOUNT_KEYAdmin service account JSON for setup ops.

Notes

  • Azure credentials are also available by sourcing /etc/profile.d/instruqt-env.sh in any login shell.
  • To run admin operations as the GCP admin account without polluting the user-visible context, set CLOUDSDK_AUTH_CREDENTIAL_FILE_OVERRIDE for the duration of the command.
  • Variables are scoped per cloud resource block. A track with two AWS accounts gets two complete sets of INSTRUQT_AWS_ACCOUNT_* variables — one per resource name.
  • Set custom variables across hosts with agent variable set KEY VALUE and read them with agent variable get KEY. They surface in assignments via [[ Instruqt-Var key="KEY" hostname="HOST" ]].
